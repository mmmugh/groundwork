**Goal:** Groundwork public at https://github.com/mmmugh/groundwork and https://mmmugh.github.io/groundwork/: every parked
fix done and proven on the Mac, both runtimes re-released with the boxes' two java.net corrections, the repository's
public face written, then one fresh-start commit pushed, three releases published and the site deployed, each outward step
on the author's explicit go at that moment.

**Architecture:** two halves. The local half (Tasks 1-10) runs on branch plan-4b in ~/groundwork exactly as Plans 3b and 4
did: a fresh implementer per task, a review after each, a final panel, one fix wave, merged into main on the author's go. The
publish half (Tasks 11-15) runs on main, by the controller only, never a subagent: it cuts the fresh-start commit, then

build/DecisionsTest.java, docs/superpowers/plans/README.md. Publish.java loses its bookkeeping: site/ is emptied before each

**Tech stack:** Java 25 (pinned Temurin; single-file programs, no build tool), Node 25.9.0, playwright-core 1.63.0
(Chromium, WebKit, Firefox), POSIX shell and bash, GitHub Actions YAML, gh 2.90.0, gitleaks 8.30.1 (the CI pin; the same

**Spec:** DESIGN.md and the decisions (the worksheet's D1-D109 until Task 5 writes DECISIONS.md). Read the research note a

4. **A reader's box connects to its own machine** (localhost, 127.0.0.1): it gets the JDK's ConnectException,

5. **A contributor on a Mac renames a volume's folder by case only:** the next build still publishes it under its new

## If something goes wrong after a push [D-13]

The plan forbids a force-push, and a force-push would not remove a commit anyway (forks and by-hash access keep it). So:

- **Before the flip (the repository is private):** a leak found in the pushed root, its message or a release means
  deleting the repository, not repairing it. The author adds the scope (`! gh auth refresh -h github.com -s
  delete_repo`), then **(go)** `gh repo delete mmmugh/groundwork --yes`; the fix lands on main by a normal commit, Task 11
  Steps 7-9 cut, scan and adopt a new root, and Task 12 starts again from Step 1. Never repair a pushed root with a follow-up commit: the
  root's hash is what the scans and the release tags pin.
- **A wrong release while it is a draft:** `gh release delete <tag> --yes` (a draft has no tag yet) and create it again.
  Once published: `gh release delete <tag> --cleanup-tag --yes`, then recreate; if immutable releases turn out to be on
  (Task 12 Step 1 reads it), a published release cannot change and its tag name may not return, which costs a new version
  name, new release-url.txt files and a new root: that is why every release is verified as a draft first (V-15).
- **After the flip:** treat whatever leaked as disclosed. At once **(go)** delete the repository (and, if Pages is up,
  `gh api -X DELETE repos/mmmugh/groundwork/pages`) to stop further copies; rename or rotate what leaked; if it was a
  credential, revoke it and ask GitHub Support to purge cached views; then recreate from a new root. Say all of this to
  the author plainly; none of it unpublishes what was already copied.

# Security

Groundwork runs readers' Java programs in their own browsers. A box's program is compiled and run in a Web Worker that
closes its doors to the network before the program starts; the scratchpad's jshell runs in its own worker, whose virtual
machine has no socket support (DESIGN.md, sections 1 and 2). If you find a way around either—a box or the scratchpad that
reaches the network, runs JavaScript of its own, reads another page's data or escapes its worker—or a build that
publishes something it must not, please report it privately.

## How to report

Use GitHub's private vulnerability reporting: open this repository's **Security** tab and choose **Report a
vulnerability**. Only you and the maintainer see the report until an advisory is published.

Please do not open a public issue, pull request or discussion about a vulnerability.

## What to include

The program or the steps, the browser and its version, what you expected and what happened.

## Scope

In scope: this repository's own code (the page and runner in `web/`, the build in `build/`, the runtime patches in
`runtime/patches/`, the jshell front end in `runtime/jshell/`) and the runtime releases published from it. A flaw in
TeaVM, teavm-javac, Ristretto or a browser that does not depend on how the course uses it belongs with that project.
