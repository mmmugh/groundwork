# Java Foundations: implementation roadmap

**Spec:** [DESIGN.md](../../../DESIGN.md). Decisions D1 to D29 and R1 to R4, with their evidence, are
in [the session worksheet](../../../WORKSHEET-2026-09-26-java-port.md). Spike sources and reports are in
[spike/2026-09-27/](../../../spike/2026-09-27/).

The spec covers six subsystems, so it is built as six plans, in this order. Each plan produces
software that works and is tested on its own. Plan 1 is written in full. Each later plan is written
with superpowers:writing-plans at the start of the session that executes it, against the code that
exists by then; this file fixes their scope and order so no session has to rediscover it.

| # | Plan | Delivers | Needs |
|---|---|---|---|
| 1 | [Runtime](2026-09-27-plan-1-runtime.md) | `runtime/`: the teavm-javac fork rebuilt from pinned sources; a Node runner that survives runaway, out-of-memory and stack-overflow programs; the differential test against a pinned JDK with an explicit known-differences list; JDK message text, numeric fixes and `HashMap` order (clean room); `Random` held steady per Run; a checksummed release bundle with licenses and corresponding source | nothing |
| 2 | Build | `build/Build.java`: volumes, Markdown rendering, boxes, the private-content whitelist and guard, the output audit, the differential gate over every example, the vocabulary gate (javac tree), the `.java` bundle; fetch-and-verify of the runtime release | Plan 1 |

Standing rules for every plan (from DESIGN.md and the author's instructions):

- Nothing is pushed, no GitHub repository is created, nothing is published, without the author's
  explicit go-ahead at that moment. Local commits are fine and carry their reasoning at length.
- The leak hooks stay on (`git config core.hooksPath .githooks`). Never commit with `--no-verify`.
- Port 8731 belongs to the Python course's dev server. Never bind it.
- Clean room: fidelity patches to TeaVM are written from the pinned JDK's observed behavior and public
  Javadoc only. Whoever has read the relevant OpenJDK source does not write that patch.
- Every gate is proven by breaking something on purpose, and the commit message says so.
- Prose follows the author's formatting rules: closed em dashes, American spelling, "course" not
  "book".
- Keep the worksheet current; append a checkpoint per task, and a FEEDBACK line when something bites.
