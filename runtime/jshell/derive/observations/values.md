## Surprises

- The `$N` the tool prints is the snippet number, which is not the number the public API puts in the variable's name: `'a'` as the fifth snippet prints `$5` in the tool while the event names it `$3` (values.57 and values.58). Typing the printed name works; the API-style name does not exist (values-10#4).
- Truncation (49 characters, ` ... `, 26 characters, when the value text is over 80) only happens after a declaration or a simple assignment. A bare name entry, a `$N` expression and a compound assignment print the full value, so the same variable can print short and long forms (values.14 to values.18).
- Postfix `x++` prints the old value and the variable holds the new one; a compound assignment prints `$N`, a simple assignment prints the variable's name (values.47 to values.49).
- A `toString` that throws prints an empty value with no message at all, in both engines, and the API reports a null value for it (values.43).
- An empty StringBuilder, an empty-string `toString` and a throwing `toString` all print `$N ==> ` followed by the newline, so they cannot be told apart in the output.
- Output captured from a cut surrogate pair shows `?` at the cut (values.19); that is the capture's encoding of a lone surrogate, so it is probably not a character the reader would see in a terminal that handles it differently.
- Chained assignment `c1 = c2 = 6` prints only `c1 ==> 6`, and `int c1, c2; c1 = c2 = 4` prints three lines (the two declarations with their defaults, then the assignment).
- Probes removed during the work because they broke the observation run (see the summary): an object whose `toString` returns null ended the `--execution local` session silently with exit status 1 and no output file (the default engine printed an empty value, `$5 ==> `, for it); a char or String holding a lone surrogate (`'\ud83d'`) made the event probe exit with an error; lambda values and `Thread.currentThread().getName()` are nondeterministic (`$Lambda/0x...@hash`; `main` in the default engine against a `Thread-NN` name in the local one), and an array inside a list printed an identity hash.

## Open questions

- What the local engine does with a `toString` that returns null: the session died before any output, so there is no evidence here (the default engine printed an empty value).
- Whether the truncation cut points count UTF-16 units or something else is only settled for the cases quoted (a pair split in the middle); a high surrogate left at the head was not observed separately from the tail.
- Whether the 80-character threshold is on the value text alone (it is for every case quoted: `name ==> ` is not counted) for types whose printed form includes a type prefix, such as `int[24] { ... }`, is consistent with the array boundary quoted, but only the int array was bracketed.
- Value lines for variables whose type is a user class that is later redefined (the value printed after a class redefinition) were not probed here.
